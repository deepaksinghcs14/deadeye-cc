How it decides

A kernel, not a keyword list

Every other router matches words in your prompt — "architecture" appears, escalate. deadeye reads the shape of the actual task, then searches the model × effort grid for the cheapest cell that clears the job. The reasoning is always printable.

  • ObserveFiles in scope, recent git churn, whether adjacent tests exist, how specific the request reads. Four cheap, deterministic signals — no LLM call, no network.
  • DecideCost is a function of model and effort together — Sonnet at high competes with Opus at low. The kernel picks the cheapest cell that clears the evidence-backed floor, not a tier chosen by rule of thumb.
  • EnforceRewrites the model when a subagent spawns — only if you left it unset. Filters output before it lands. Asks before multi-file edits that skipped a plan.
  • LearnWhen you explicitly pick a bigger model than it recommended, that's logged and raises the bar for that kind of task next time. Revert/test-fail detection is still on the list.

Measured, not estimated

Every number here traces to a logged decision

Bytes kept out of context are logged with the rule that fired. Decisions are logged with their inputs. There is no coefficient anywhere that turns a tool-call count into a savings figure — if it's not a row in decisions.jsonl, it isn't printed.

The rule behind everything

Unknown routes up

Missing evidence never buys a cheaper model. If deadeye can't tell how far a change reaches, it assumes far. Downshifting requires positive evidence above a confidence threshold; upshifting is free.

  • Wrong expensive is recoverableIt costs money. Wrong cheap costs you a bad diff and the session it takes to find it.
  • Never writes your settingsdeadeye keeps its own state in one JSONL file. Your settings.json is yours.
  • Fails open, alwaysAny error in any hook and the call passes through untouched. A policy layer must never block your work.

Install

Two commands

/plugin marketplace add deepaksinghcs14/deadeye-cc /plugin install deadeye@deadeye

macOS and Linux need nothing else. Windows: grab the binary from Releases first — self-bootstrap there isn't built yet.

Turn it off

DEADEYE=off everything DEADEYE_PREPROCESS=off output rewriting DEADEYE_GATE=off plan gate
Does it phone home?

No. One JSONL file on your machine, at ~/.deadeye/. No hosted service, no API keys, no telemetry.

Will it make Claude dumber?

That's the failure mode it's built against. Unknown scope routes up, and downshifting needs positive evidence. If you find a case where it under-powered a task, that's a bug — file it with the /deadeye-route output.

It rewrote a command I needed in full.

Rules are conservative by design and each one can be disabled individually via config. A rule that loses information the agent needed is a broken rule — file it with the command.

Can it change my main session's model?

No, and nothing can do that reliably mid-session. deadeye enforces on subagents, where the spend concentrates, and advises on the main session.

Why "deadeye"?

Because efficiency isn't spending less — it's not missing.
