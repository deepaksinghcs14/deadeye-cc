optional · opt-in · local

Run a local classifier for deadeye's typed decisions.

deadeye's routing judge answers one question — how much capability does this subtask need — by shelling out to claude -p --model sonnet. That call is the only thing in deadeye that blocks a hook response on a model call. Laya (Apache 2.0) answers typed choice / score / yes-no questions locally, so it can stand in.

the contract

deadeye does not ship, install, or supervise Laya

Laya is Python. deadeye is a single static Go binary with no runtime dependencies, and bundling an interpreter plus ~843MB of weights into six release binaries would trade that away for one optional feature. Apache 2.0 would permit redistribution — the objection is practical, not legal.

So the whole contract is an endpoint: you run laya-serve, deadeye points at it, and every call site falls back to today's exact behavior the moment it stops answering. With mode.laya at its default off, nothing here runs and deadeye behaves bit-for-bit as it did before this existed.

Cost, stated plainly. ~843MB of weights for the English checkpoint. 193–464ms per call on CPU with the model resident — the widely quoted 32.8ms is a T4 GPU figure. A cold checkpoint load costs several seconds, which is why the server has to stay running.

setup

The skill does all of this and verifies it

In Claude Code:

/deadeye-laya install

By hand, if you'd rather:

python3 -m venv ~/.deadeye/laya-venv
~/.deadeye/laya-venv/bin/pip install "laya[serve]"

# binds 0.0.0.0:8000 — leave it running, preloaded so the first
# real decision doesn't pay the cold checkpoint load
LAYA_PRELOAD=1 ~/.deadeye/laya-venv/bin/laya-serve

Then point deadeye at it and start on the bottom rung:

deadeye config set laya.endpoint http://127.0.0.1:8000
deadeye config set mode.laya shadow

deadeye laya health   # reachability
deadeye laya test     # one real tier question, end to end

Keep the endpoint on loopback. Nothing stops you pointing laya.endpoint at another host, but then every task description deadeye classifies leaves this machine — so deadeye laya status and deadeye doctor both warn when it isn't loopback. What gets sent is the task description or, for the two gate checks, the prompt as you typed it.

Useful laya-serve environment variables: LAYA_DEVICE=cuda if you have a GPU, LAYA_PORT, LAYA_THREADS, and LAYA_API_KEY for a bearer token. If you set a token, deadeye reads it from the environment by name (laya.api_key_env, default LAYA_API_KEY) — never write the token itself into config.json, which deadeye config prints.

the ladder

Four rungs, and you start at the bottom

mode.layaAskedRecordedActed on
off (default)no——
shadowyesyesno
adviseyesyesno — shown in decision reasons
authoritativeyesyesyes

Why a ladder and not a switch. Laya's untuned accuracy on typed decisions is 0.362 on its vendor's own evaluation, against ~0.33 for a three-way coin flip (0.766 fine-tuned, which needs roughly 30k labelled examples and GPU hours). Every published figure for Laya is vendor-self-reported; we found no independent evaluation. Shadow mode lets you discover how it does on your traffic at zero risk, before anything routes on it.

Only the rungs that act on an answer wait for it. On shadow, and for the plan-gate and workflow-hint checks on advise too, deadeye asks Laya off the critical path and records the answer when it arrives — your tool calls and prompts are never delayed to collect a measurement. advise waits on the routing question (it prints the answer in the reason you read) and authoritative waits wherever the answer decides something. That's the latency you opt into by climbing.

Check the evidence before promoting:

/deadeye-stats laya      # or: deadeye laya agreement

That reports agreement per call site over 30 days — not accuracy. On shadow and advise, “actual” is whatever the existing mechanism chose, which is not ground truth either, so a high number means the two concur, not that either is right. Treat a site below ~60% as a reason not to promote, and fewer than ~50 verdicts as not enough to judge.

Shadow mode has a second payoff: it accumulates the labelled task → tier data that fine-tuning would need. That is the only real route to the 0.766 figure, and you can't invent the dataset.

Demoting costs nothing and loses no recorded data:

deadeye config set mode.laya shadow

turning it off

Four ways, all instant, none lose data

deadeye config set mode.laya shadow   # back down the ladder, keep measuring
deadeye config set mode.laya off      # stop calling it
DEADEYE_LAYA=off claude               # env kill switch, wins over config.json

Clearing the endpoint (laya.endpoint) disables it too, whatever mode.laya says. And DEADEYE=off turns off everything deadeye does, Laya included.

Or simply stop laya-serve: deadeye fails open on an unreachable endpoint, so killing the server disables every call site with no config change at all. That one is worth stating plainly — a dead endpoint and a disabled Laya are indistinguishable in behavior, by design. It's also why deadeye doctor carries a laya row: otherwise “it stopped working” and “it's off” look the same.

Recorded verdicts survive all of these, so you can turn it off and still read /deadeye-stats laya afterwards.

call sites

Six places, all opt-in, all fail-open

SiteQuestionWhat Laya may do
Routing judgetier 0 / 1 / 2On authoritative, replaces the claude -p call for exactly the ambiguous cases it exists for — the one blocking model call in the product.
Complexity signalhow much capability?An optional seventh signal beside the six heuristics. Added only on authoritative, and skipped quietly below a certainty floor — the kernel takes the minimum confidence across signals, so a hedging classifier would otherwise make every route pricier.
Plan gatedoes this need a plan first?May only confirm or suppress a gate the heuristic already fired — never fire one itself. Suppression is the direction where being wrong is cheap.
Workflow hintgenuinely parallel work?Same confirmer-not-trigger contract as the plan gate.
Tier-sample screenwas this over-routed?A free local screen on every confident high-tier route, escalating only disagreements to a paid confirmation. This is what makes /deadeye-stats disagreement dense instead of a 1-in-10 sample.
deadeye missesis this commit a bug fix?Replaces a fix|bugfix|revert regex, catching the fixes that never say “fix”. Offline, so latency is irrelevant — the lowest-risk site of the six.

troubleshooting

deadeye doctor carries a laya row, because a dead endpoint looks exactly like Laya being off — correct fail-open behavior, and a terrible thing to debug without a signal.

deadeye laya test returns tier 1 or 2 for a variable rename. The endpoint works; the classifier is wrong on an easy case. Leave mode.laya at shadow.

Reachable, but no usable answer. The checkpoint probably hasn't finished loading — check the laya-serve output and retry.

First call is slow. Expected: that's the cold load. Run it again, and start the server with LAYA_PRELOAD=1.

Nothing recorded. Either no eligible decision has happened yet, or the endpoint isn't answering. deadeye laya health distinguishes them.

Upstream is very new. Laya was released 2026-09-18 and has been shipping roughly three releases a day. Treat breaking changes as likely rather than hypothetical, and pin a version in your venv if that matters to you.
